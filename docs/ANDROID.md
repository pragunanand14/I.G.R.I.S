# IGRIS on Android

The Android app is the same IGRIS as the desktop app: the same `igris-core`
(AI and model routing, context, memory, conversations, orchestrator and tasks,
tool executor with permissions/approvals/audit, productivity, voice backends),
the same app crate (`src-tauri`, built for Android with Tauri's mobile target)
and the same React UI, adapted for phones. What changes is the device layer.

## What IGRIS can do on a phone

| Capability | Phone | Notes |
|---|---|---|
| Chat, streaming, model routing, context budgeting | ✅ | core, unchanged |
| Memory, tasks, reminders, timers, calendar | ✅ | reminders fire as Android notifications |
| Web search / reading pages | ✅ | when a search key is configured |
| Images and PDFs in chat | ✅ | |
| Voice (mic in the chat, cloud STT/TTS) | ✅ (untested on device) | Android asks for the microphone the first time |
| List the phone's apps, open one | ✅ | `list_phone_apps`, `open_phone_app` (LOW: runs with the usual policy) |
| Battery, network, device model | ✅ | `device_status`; also feeds the System page battery |
| Open links | ✅ | `open_url` through Android's opener |
| Files, terminal, screenshots, operator mode (controlling the screen) | ❌ | not offered to the model and not claimed in its prompt |

The phone tool list is built in `src-tauri/src/tools/standard.rs` (`#[cfg(mobile)]`
registry, 25 tools). The system prompt has a phone variant
(`igris-core/src/core/prompt.rs`, `DeviceKind::Phone`) that describes exactly
these capabilities and says what the phone app can't do.

## How it is built

- `src-tauri` is one Tauri app for both platforms. `#[cfg(desktop)]` /
  `#[cfg(mobile)]` select the platform parts: on desktops the overlay, global
  hotkeys, Windows driver, browser control and desktop tools; on Android the
  phone tools. Desktop-only crates (global shortcuts, recycle bin, OS battery)
  are not compiled for Android.
- `plugins/tauri-plugin-igris-device` is a Tauri plugin with a Kotlin side
  (`android/`): `listApps` (launcher-visible apps only, via a `<queries>`
  declaration — no `QUERY_ALL_PACKAGES`), `launchApp`, `status` (battery via
  `ACTION_BATTERY_CHANGED`, network via `ConnectivityManager`). It exposes **no
  webview commands**: only IGRIS's Rust tools call it, so every use goes through
  the executor (permission level, approvals, audit log).
- `src-tauri/gen/android` is the Android Studio project generated by
  `tauri android init` (committed, with IGRIS launcher icons).
- TLS: on Android, HTTPS is verified against bundled Mozilla roots
  (`igris-core/src/net.rs`); the platform verifier needs JNI setup that Tauri
  doesn't provide. User-installed CAs are therefore not trusted on Android.
- UI: phones get bottom navigation, no window buttons, safe-area padding, a
  conversation panel instead of the history column, and no desktop-only pages
  or sections (Projects, shared folders, desktop applications).

## Building

Needs the Android SDK + NDK, JDK 17+, and the Rust targets:

```text
rustup target add aarch64-linux-android x86_64-linux-android
export ANDROID_HOME=… NDK_HOME=…
npx tauri android build --debug --apk --target aarch64   # phones
npx tauri android dev                                    # run on a device/emulator
```

CI does this in [`.github/workflows/android.yml`](../.github/workflows/android.yml):
it builds a debug APK for x86_64 and arm64 (uploaded as the
`igris-android-debug-apk` artifact) and runs `scripts/android-smoke.sh` on an
Android 14 emulator.

## Configuring the AI provider (current limitation)

Keys are still read only from a `.env` file in IGRIS's config folder (the path
is shown in Settings → AI, which also has the button to reload it). On a phone that folder is private to the app, so
today it can only be filled on a debug build:

```text
adb push .env /data/local/tmp/igris.env
adb shell run-as dev.igris.app cp /data/local/tmp/igris.env <config folder>/.env
adb shell rm /data/local/tmp/igris.env
```

An in-app way to enter a key (stored only in the app's private storage, never
returned to the UI) is the obvious next step; it needs a decision on the "keys
never in the frontend" rule, so it hasn't been built.

## Test results

Emulator smoke test (GitHub `ubuntu-latest`, Android 14 / API 34 x86_64
emulator, no AI provider) — run `37514700998`, all checks PASS:

| Check | Result |
|---|---|
| APK installs, cold start | PASS (3.4 s to first frame) |
| IGRIS starts: all 11 migrations, `APP_STARTED` | PASS |
| Phone tool set registered | PASS (25 tools) |
| Kotlin plugin answers (`PHONE_READY`) | PASS (17 apps, Wi-Fi, battery readable, SDK 34) |
| No crash in logcat | PASS |

Later runs also check the screen (UI dump): the UI rendered and shows the
backend's own AI-status message, proving the webview ↔ Rust IPC works.

**Not tested yet:** a physical phone; a chat with a real AI provider on
Android; voice on a device; opening an app by voice/chat end to end; release
(signed, minified) builds. The debug APK is large (≈600 MB: unstripped debug
symbols for two architectures); release builds are much smaller.
